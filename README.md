# Dentist App — запись пациентов

Календарь записи: выбираешь свободный слот, пациента из базы (или создаёшь нового) и услугу.
Все устройства (компьютер, телефон) работают с одним сервером и одной базой PostgreSQL,
поэтому видят одни и те же данные.

- **Бэкенд:** Go 1.22, стандартный `net/http`, драйвер [pgx](https://github.com/jackc/pgx)
- **База:** PostgreSQL 17 в Docker
- **Фронтенд:** React 19 + TypeScript, Vite, TanStack Query, React Router

## Запуск локально

Нужны Go 1.22+, Node.js 20+ и Docker Desktop. Команды ниже — для PowerShell
(Windows PowerShell 5.1 не понимает `&&`, поэтому каждая команда на своей строке).

**1. База** (один раз; контейнер потом сам стартует вместе с Docker Desktop):

```powershell
docker compose up -d
```

**2а. Обычная работа — один сервер.** Go-сервер отдаёт и API, и интерфейс: собранный фронтенд
встраивается в бинарник. Интерфейс нужно пересобирать после изменений в `frontend/`
(`npm install` — только в первый раз и после изменения зависимостей):

```powershell
cd frontend
npm install
npm run build
cd ..
go run ./cmd/server
```

Открывать **http://localhost:8080**. Если интерфейс не собран, по этому адресу будет подсказка, а API работает.

**2б. Разработка интерфейса — два терминала.** Vite пересобирает страницу на лету при каждом
сохранении файла и проксирует `/api` (включая поток событий) на Go-сервер:

```powershell
go run ./cmd/server
```

```powershell
cd frontend
npm run dev
```

Открывать **http://localhost:5173**.

Если `npm` «не является именем командлета» — терминал открыт до установки Node.js, откройте новый.
Если `bind: Only one usage of each socket address` — порт 8080 уже занят другим запущенным
экземпляром сервера; остановите его или запустите на другом порту: `$env:HTTP_ADDR=":8081"`
(тогда поправьте и прокси в `frontend/vite.config.ts`).

### Несколько устройств

Изменения приходят на все открытые устройства сразу (обычно за доли секунды): сервер держит поток
[Server-Sent Events](https://developer.mozilla.org/ru/docs/Web/API/Server-sent_events) `/api/events`
и после любого изменения шлёт в него сигнал, а страница перезапрашивает то, что на экране.
Зелёная точка в шапке — связь есть; серая — связи нет, тогда календарь обновляется раз в 15 секунд,
а после восстановления связи сам подтягивает всё пропущенное.

### С телефона

Телефон должен быть в той же Wi-Fi-сети, что и компьютер. Откройте на нём адрес компьютера в сети:
`http://192.168.x.x:8080` (в режиме 2а) или `http://192.168.x.x:5173` (в режиме 2б — Vite печатает
его при запуске в строке `Network:`).

Если страница на телефоне не открывается — входящие подключения блокирует брандмауэр Windows.
В «Параметры → Сеть и Интернет → Wi-Fi → свойства сети» смените профиль на **«Частная»** и разрешите
доступ, когда Windows спросит. Для `go run` Windows будет спрашивать при каждом запуске (бинарник
каждый раз собирается в новую временную папку), поэтому надёжнее разрешить порт один раз —
в PowerShell от имени администратора:

```powershell
New-NetFirewallRule -DisplayName "Dentist app" -Direction Inbound -Protocol TCP -LocalPort 8080,5173 -Action Allow -Profile Private
```

При старте сервер сам применяет миграции из `internal/db/migrations/`.

Порт базы — **5433**, а не стандартный 5432: на 5432 уже работает PostgreSQL 15,
установленный в Windows (служба `postgresql-x64-15`), и он с Docker не конфликтует.

Настройки через переменные окружения (значения по умолчанию подходят для docker-compose):

| Переменная     | По умолчанию                                                         |
|----------------|----------------------------------------------------------------------|
| `HTTP_ADDR`    | `:8080`                                                              |
| `DATABASE_URL` | `postgres://dentist:dentist@localhost:5433/dentist?sslmode=disable`  |

Проверки: `go test ./...` для бэкенда, `npm run build` в `frontend/` (типы + сборка).

## Структура

```
cmd/server/            точка входа
internal/config/       настройки из окружения
internal/db/           подключение к БД и миграции (SQL встроен в бинарник)
internal/store/        запросы к PostgreSQL
internal/api/          HTTP-обработчики, валидация, поток событий (events.go)

frontend/frontend.go   встраивает собранный интерфейс (dist/app) в Go-бинарник
frontend/src/
  api.ts               типы и вызовы API
  live.ts              подписка на /api/events и индикатор связи
  pages/               Календарь, Пациенты, Услуги
  components/          сетка календаря, форма записи, выбор пациента, модальное окно
  lib/dates.ts         работа с датами и настройки сетки (шаг слота, рабочие часы)
```

Шаг сетки (30 минут) и рабочие часы (8:00–21:00) задаются константами в `frontend/src/lib/dates.ts`.

## API

Все ответы — JSON. Ошибка: `{"error": "текст для пользователя"}`.

| Метод  | Путь                       | Описание                                    |
|--------|----------------------------|---------------------------------------------|
| GET    | `/api/health`              | проверка, что сервер жив                    |
| GET    | `/api/events`              | поток SSE: `data: changed` после изменений  |
| GET    | `/api/patients?q=&limit=&offset=` | поиск по ФИО и телефону              |
| POST   | `/api/patients`            | создать пациента                            |
| GET    | `/api/patients/{id}`       | пациент                                     |
| PUT    | `/api/patients/{id}`       | изменить пациента                           |
| DELETE | `/api/patients/{id}`       | удалить (нельзя, если есть записи — 409)    |
| GET    | `/api/services`            | все услуги                                  |
| POST   | `/api/services`            | создать услугу                              |
| GET    | `/api/services/{id}`       | услуга                                      |
| PUT    | `/api/services/{id}`       | изменить услугу                             |
| DELETE | `/api/services/{id}`       | удалить (нельзя, если используется — 409)   |
| GET    | `/api/appointments?from=&to=` | записи за период (RFC 3339)              |
| GET    | `/api/appointments?patient_id=` | история записей пациента               |
| POST   | `/api/appointments`        | создать запись                              |
| GET    | `/api/appointments/{id}`   | запись                                      |
| PUT    | `/api/appointments/{id}`   | изменить / перенести запись                 |
| DELETE | `/api/appointments/{id}`   | удалить запись                              |

Записи не могут пересекаться по времени — это проверяет сама база (exclusion constraint),
при попытке занять занятое время API вернёт `409`.

### Примеры

В PowerShell используйте `curl.exe` (просто `curl` там — это другая команда).

```bash
curl.exe -X POST http://localhost:8080/api/services -H "Content-Type: application/json" -d "{\"name\":\"Консультация\",\"duration_minutes\":30,\"price\":1000}"

curl.exe -X POST http://localhost:8080/api/patients -H "Content-Type: application/json" -d "{\"last_name\":\"Иванов\",\"first_name\":\"Иван\",\"middle_name\":\"Иванович\",\"phone\":\"+7 916 123-45-67\"}"

curl.exe -X POST http://localhost:8080/api/appointments -H "Content-Type: application/json" -d "{\"patient_id\":1,\"service_id\":1,\"starts_at\":\"2026-11-03T10:00:00+03:00\",\"ends_at\":\"2026-11-03T10:30:00+03:00\"}"

curl.exe "http://localhost:8080/api/appointments?from=2026-11-02T00:00:00%2B03:00&to=2026-11-09T00:00:00%2B03:00"
```

## План по частям

1. **Бэкенд + БД** — пациенты, услуги, записи (готово)
2. **Фронтенд на React** — календарь, запись в свободный слот, справочники, вёрстка под телефон (готово)
3. **Несколько устройств** — мгновенные обновления через SSE, интерфейс встроен в Go-сервер (готово)
4. **Вход по паролю, деплой на сервер с HTTPS**, установка на телефон как приложение (PWA)
